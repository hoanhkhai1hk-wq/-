# AgroLake 农智数湖

兴智杯无人农场数据治理项目。围绕农田影像、地块属性与复核记录，制作来源可查、质量可解释的数据治理和田块识别原型。

## 当前进度

第一版治理原型已可运行：JPG/PNG 影像、CSV 属性、JSON/TXT 记录接入，内容去重与版本留痕，质量检查、单位和地物类别标准化，场景关联、问题处置复检及报告导出。36 项核心验收通过；演示资料全部为人工合成，仅用于操作与规则验证。

本机已取得并核对 FTW 8 波段测试影像与 v1 CC-BY 权重，但完整模型环境与真实推理尚未通过。GeoTIFF 接入、DeepSeek、真实农业样本评估和参赛材料仍待完成。普通 RGB 治理页面不能代替 FTW 双时相多波段模型。

## 启动与试用

使用 Python 3.11 与项目独立环境，按 [本地启动说明](docs/本地启动.md) 安装、生成可选演示资料并启动。已启动的本机页面地址为 [AgroLake](http://127.0.0.1:8505/)；该地址只在运行服务的电脑上有效。

试用顺序：治理概览 → 数据目录 → 场景关联 → 问题处置 → 报告导出。导入自己的文件时填写来源与场景；CSV/JSON/TXT 使用 UTF-8，CSV 每份文件对应一个场景。地块面积字段是输入声明及单位换算，不是模型测得的面积。规则与统计口径见 [数据字典](docs/数据字典.md)。

固定验收命令：

```powershell
& .\.venv-p0\Scripts\python.exe scripts/p0/run_acceptance.py
```

## 开发方式

WorkBuddy 按明确任务编写代码并运行，Codex 负责技术协调、代码复核和实际验收。每个通过检查的功能保存独立 Git 提交，再同步到本私有仓库。具体流程见 [GitHub 协作流程](docs/GitHub协作流程.md)。

主要交付目标为 Streamlit 网页、SQLite 目录与质量治理、真实 FTW 识别以及基于入库事实的 DeepSeek 问答和报告。完成状态以实际代码和运行证据为准，当前版本先交付治理原型。

环境、原始数据、权重、数据库和本地协作资料由 `.gitignore` 排除。仓库保存审阅过的源码、配置样例、依赖记录和使用说明。

第三方代码、模型与数据来源见 [第三方登记](THIRD_PARTY.md)。

本仓库保留最初的兴智杯 README 与初始提交历史。
