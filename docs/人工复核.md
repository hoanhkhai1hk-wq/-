# 人工复核记录：使用与边界

版本 0.1.0（2026-10-15，DEV-20261015-013）。面向 Windows PowerShell、零基础。
本页说明如何在“田块识别”页对**成功识别任务**记录人工意见，并查看当前意见、历史与导出。

> 人工复核只记录**人工填写的声明**，不是真值、不是精度证据，也不改变模型输出；
> 复核人只是本机署名，不是已认证身份。

## 一 它能做什么

- 对**任务整体**（整幅识别结果）填写结论和原因。
- 对**某个已存在的候选区域**（区域编号 `field_id`）单独填写结论和原因。
- 三类固定结论（中文显示）：**可用**（`accepted`）、**存疑待核实**（`questioned`）、**不采用**（`rejected`）。
- 保存更改会**追加一条新记录**；从意见A改为B再改回A，也会保留三条历史。
  紧接着的重复点击仍复用当前请求号，不重复写入。历史永不覆盖，可逐条回看。
- 当前意见按目标（任务整体 / 每个区域）取**记录号最大的一条**；任务整体结论与区域结论**分开**，
  不把一处区域可用当成整个任务已确认。
- 导出 **UTF-8 CSV / JSON**，包含开始导出时所选任务的全部历史快照；导出期间新追加的意见
  留待下次导出。下载只读，不写数据库。本地原型每个任务最多500条复核历史，达到上限后
  明确拒绝新增，原历史仍可查看、导出和按同号重试；不自动删除或覆盖。

## 二 它不做什么

- 不改掩膜、类别数、模型输入输出；不据此声称真值、精度提升、真实田块数或平方米。
- 不代表 T09 治理对照、DeepSeek 问答或比赛交付已完成。
- 不提供删除或改写接口；只能追加，历史始终可查。
- 不是已认证身份系统；`reviewer` 就是你在本机键入的署名。

## 三 在网页里怎么用

1. 先按 [网页识别说明](网页识别.md) 启动识别服务与网页，在第 8 页“田块识别”提交一次 8 波段 TIFF
   并等到**已成功**。失败或中断的任务保持原提示，不显示复核面板。
2. 展开成功结果后，找到“**人工复核记录**”面板：
   - “当前意见（按目标取最新一条）”：任务整体、各候选区域当前的结论与复核人；未填写的显示“未复核”。
   - “填写任务整体意见”“填写某个候选区域意见”：选择结论、填写复核人署名与具体原因，点保存。
   - 复核人 1–80 字，原因 1–2000 字，均是必填；未填会就地提示。
   - “复核历史（不可覆盖，按记录号递增）”：逐条列出，含请求号与输入/模型快照。
   - “导出复核记录”：CSV 与 JSON，二者都注明“人工声明”与“像素/无真值”边界。
3. **只有点击“保存”才写入**。普通刷新、切换任务、切换历史、下载都不会写库。
   - 同一次填写重复点击、或再次点“保存”而内容未变：复用**同一请求号**，服务端按请求号幂等，
     不会重复写入（提示“已存在同一复核意见，本次未重复写入”）。
   - 修改了署名/结论/原因后再保存：按新的意图**追加**一条。
4. **回执未知时**（提交超时、响应不完整）：提示“尚未确认”，并给出“**重试提交（同一请求号）**”；
   重试保持同一请求号，不会悄悄换号重复写。
5. 切换历史任务时，看到的是**该任务自己的**当前意见与历史，不会串用其它任务的意见或下载。

## 四 结果怎么读（重要边界）

- 人工结论是**声明**：`可用/存疑待核实/不采用` 只代表填写人的判断，没有独立真值支撑。
- 面积只以像素计，未取得经核验地理参考前**不换算平方米**；候选区域不是真实田块数。
- 导出文件名：`reviews-job-<job_id>.csv`、`reviews-job-<job_id>.json`。
  - **CSV**：首行与次行以 `# ` 开头，包含快照截止记录号、条数、“人工声明边界”与“转义规则”，不是数据行；
    为防止表格软件把以 `= + - @`（或制表/回车）开头的文本当公式执行，检测时也跳过前导空白/BOM；
    这些文本会**前置单引号 `'`**。下载未取全或分页异常时会隐藏下载按钮并明确提示。
  - **JSON**：保留原始值（含公式样文本），并含 `boundary`（人工声明边界）与 `csv_escaping` 说明。
- 记录里保留**输入 SHA256、模型 SHA256、运行序号**快照，用来对应“这条意见看的是哪一次识别结果”；
  只导出复核表内容，不含任意路径，也不含模型权重。

## 五 接口与存储（供复核/维护）

- `POST /jobs/<id>/reviews`：JSON `{field_id(正整数或 null), decision, reviewer, note, request_id}`。
  - 服务端从该作业取得快照与创建时间，客户端**不能**指定快照/时间/记录号；出现 `review_id` 等未知字段会被拒绝。
  - 未知作业/区域返回 404；非成功作业返回 409；非法/超长/越界请求返回 400；复核正文超过 16 KiB 返回 413。
  - 同一 `request_id` + 同一内容复用同一记录；内容、任务或区域不同则返回 409；并发同号只落一行，失败回滚。
- `GET /jobs/<id>/reviews`：返回 `job_id`、`reviews`（一页）、`latest`（task / regions 最新意见）、
  `pagination`（`after_id`/`until_id`/`limit`/`has_more`/`next_after_id`）。默认/最大每页200；
  第一页给出快照截止`until_id`，后续页复用该值，计数、历史与当前意见来自同一读快照。
  每任务最多500条，遍历还有50页保护，不默默交付不完整文件。
- 新表 `rec_reviews` 只在 `db.init_schema` 中 `CREATE TABLE IF NOT EXISTS` 新建；不改动 P0 既有表、
  不改 schema_version、不迁移、不删除。记录只能追加，无删除/改写 API。
- 承载逻辑集中在 `agrolake_service/reviews.py`；HTTP 路由在 `agrolake_service/server.py`；
  网页只通过 `agrolake_web/client.py` 调用服务，界面在 `agrolake_web/review_panel.py`，
  **不直接写识别数据库、不加载模型**。
