# AgroLake P0 数据字典

版本：DD-1.1.0（2026-10-15）。适用于 P0 精简治理原型，与 `agrolake/db.py`（模式 `AGROLAKE-P0-DB-1.0.0`）、`configs/semantic_rules.json`（`SEM-1.0.0`）、`configs/quality_rules.json`（`QR-1.0.0`）对应。

## 〇 业务资产身份边界

- 业务资产身份 = （规范化文件名，声明场景 `declared_scene_id`，声明来源 `source`）三者共同决定。
- 同名文件出现在不同场景或不同来源时，视为不同独立资料，不作为同一资产的版本更新；这样避免不同来源/场景的独立资料被悄悄合并。
- 只有同名、同场景、同来源的新内容，才形成该资产的新版本（`new_version_same_name`）。
- 跨文件名的完全相同内容仍按内容哈希识别为同一处重复（`duplicate_content`），只保留一个有效内容版本。
- 场景与来源可在导入后补正；补正改变当前归属与状态，不重建历史导入事件。

## 一 记录分层

| 层 | 表 | 作用 |
|---|---|---|
| 内容对象 | `objects` | 按内容 SHA256 保存的对象文件，路径相对存储根 |
| 业务资产 | `assets` | 以（文件名+场景+来源）身份键聚合的资产 |
| 资产版本 | `asset_versions` | 每次接入形成一个版本，保留来源、场景、类型、尺寸与状态 |
| 导入事件 | `import_events` | 独立记录每次导入的来源声明与事件类型，即使内容重复也保留 |
| 属性记录 | `attribute_records` | CSV 行明细，保留原始面积/单位/地物类别并给出换算与标准值 |
| 文本记录 | `text_records` | JSON/TXT 解析结果与场景一致性 |
| 质检 | `quality_checks` | 每条规则一轮结果，保留历史与复检关联 |
| 处置 | `dispositions` / `meta_history` | 处置前后记录与元数据字段变更留痕 |
| 场景 | `scenes` / `scene_members` | 场景清单与影像/属性/文本关联（审计留痕） |

## 二 关键字段

### asset_versions

| 字段 | 含义 |
|---|---|
| version_id | 版本主键 |
| asset_id | 所属资产 |
| version_no | 资产内版本序号 |
| content_type | image / attribute / text |
| object_id | 内容 SHA256（外键到 objects） |
| original_filename | 原始文件名（仅元数据，已剥离目录分量） |
| source / source_link / license_status | 来源信息 |
| acquired_at / declared_scene_id | 采集时间 / 声明场景 |
| width / height / bands / bitdepth | 影像属性（非影像为空） |
| status | active / isolated / duplicate |
| duplicate_of_version_id | 被判定重复时指向的版本 |

### import_events.event_type

| 值 | 含义 |
|---|---|
| new_asset | 新资产的首次接入（引入新内容） |
| new_version_same_name | 同名同场景同来源、内容不同，新增版本，不覆盖（引入新内容） |
| duplicate_content | 内容与既有版本完全相同（含跨文件名），仍新增版本并保留本次声明；是复制事件，不改变已有原件的当前内容指向 |

**当前内容版本口径**：每个资产取其最新一次“引入内容”的版本（即事件类型不是 `duplicate_content` 的版本）。
当前有效版本 = 当前内容版本且状态为 `active`。隔离或人工标重复的是当前内容版本时，该资产没有当前有效版本，
不自动回退到更早的历史版本。纯复制事件不推进当前内容指向。

### attribute_records

`area_raw`、`area_unit_raw` 保留原始值；`area_m2` 仅在单位为已定义的平方米/公顷/亩时换算得到，否则为空并在 `issues` 说明错误。
`category_raw` 保留地物类别原值，`category_std` 为标准化结果；未知值留空并在 `issues` 记录，不凭空识别。
必填值（场景/地块/作物）为空的行会被登记，并由 `csv_required_values` 规则阻断。

## 三 语义字典（SEM-1.0.0）

- 字段别名映射到标准列：`scene_id`、`field_id`、`crop`、`area`、`area_unit`、`category`（可选）。
- 地物类别别名映射到类别代码：`FIELD`、`FIELD_BOUNDARY`、`ROAD`、`DITCH`。
- 作物类别（`crop`，如水稻）与地物类别（`category`，如田块）是两套口径，分开管理、不互相替代。
- 单位：`m2`（1）、`ha`（10000 m²）、`mu`（666.6667 m²）。未定义单位不默认平方米，判为错误。

## 四 质量规则（QR-1.0.0）

结果状态：`pass` / `warn` / `block` / `na`。版本总体状态：有阻断→block，有警告→warn，全通过→pass，全不适用→na。

| rule_id | 适用 | 期望 |
|---|---|---|
| file_not_empty | 全部 | 空文件→block |
| size_limit | 全部 | 超建议上限→warn |
| required_source | 全部 | 缺来源→block |
| required_scene | 全部 | 未声明场景→warn |
| exact_duplicate | 全部 | 内容重复→warn |
| image_decode | 图像 | 真正解码像素后失败/截断→block（不只 verify） |
| pixel_limit | 图像 | 超像素上限→warn |
| sharpness | 图像 | 固定预览尺度拉普拉斯方差低于阈值→warn（提示，非阻断） |
| crs_applicability | 图像 | 普通图像→na |
| csv_required_columns | 属性 | 缺必填列→block |
| csv_has_rows | 属性 | 无数据行→warn |
| csv_area_units | 属性 | 面积/单位/类别错误行→block |
| csv_required_values | 属性 | 场景/地块/作物必填值为空→block |
| csv_scene_consistency | 属性 | 行内 scene_id 与声明不一致或多场景未按行关联→warn |
| text_parsed | 文本 | JSON 解析失败或编码错误→block |
| scene_consistency | 文本 | JSON scene_id 与声明失配→warn（按当前元数据重算，补正后恢复） |

清晰度规则固定：预览最长边 ≤ 512、灰度 band、`warn_below=80`、`block_below=20`。阈值未经真实农业样本校准，仅作提示。

## 五 指标口径

| 指标 | 定义 | 分母 | 排除 |
|---|---|---|---|
| quality_pass_rate | 通过版本数 ÷ 可适用版本数 | 状态为 active 的当前有效版本且存在可适用规则 | isolated、duplicate、历史版本、全部规则为 na |
| association_coverage | 三类齐全场景数 ÷ 场景总数 | 场景清单全部 scene_id | 失配/历史/隔离/重复版本不计入归属 |

**当前有效版本口径**：每个资产先选当前内容版本（最新一次引入内容的版本），再检查其状态，仅 active 计入；每个内容对象只保留唯一有效版本（跨文件名精确重复只认一处）。隔离/标重复的当前内容版本不回退旧历史；历史版本、isolated、duplicate 均不重复累加。

**场景归属口径**：文本要求当前声明与 JSON 内容一致，矛盾未处置时不归属并列出问题；属性要求行内 scene_id 与声明一致且不含多场景混用，否则不参与合格覆盖统计。`scene_members` 表保留审计留痕，不作为当前归属依据。

面积：无比例尺/地理参考时只报告像素面积，不虚构真实面积。属性面积来自用户声明，单独标注。

## 六 识别与人工复核记录（`rec_` 前缀，独立于 P0）

识别服务与 P0 共享同一 `AGROLAKE_DB` 文件，但使用独立的 `rec_` 前缀表，P0 既有表与数据原样保留、不改动、不迁移。识别侧表：`rec_meta`、`rec_inputs`、`rec_requests`、`rec_jobs`、`rec_runs`、`rec_regions`、`rec_class_counts`、`rec_artifacts`、`rec_reviews`。

### rec_reviews（人工复核记录，DEV-20261015-013）

| 字段 | 含义 |
|---|---|
| review_id | 记录主键（自增）；同一目标取最大者为其“当前意见” |
| job_id | 所属识别作业（来自 `rec_jobs`） |
| field_id | `NULL` 表示对**任务整体**复核；非空表示对某**候选区域**（对应 `rec_regions.field_id`） |
| decision | 固定枚举：`accepted`（可用）/ `questioned`（存疑待核实）/ `rejected`（不采用） |
| reviewer | 复核人署名（本机填写，1–80 字，**不是已认证身份**） |
| note | 具体原因（1–2000 字，trim 后必填） |
| request_id | 幂等请求号（唯一索引）；同号同内容复用、不同内容/任务/区域冲突 |
| content_fingerprint | 规范化内容指纹（覆盖 job_id/field_id/decision/reviewer/note） |
| input_sha256 | 服务端从该作业取得的输入快照 |
| model_sha256 | 服务端从该作业取得的模型快照 |
| run_seq | 服务端从该作业取得的运行序号 |
| created_at | 服务端生成的创建时间 |

口径：`rec_reviews` 只**追加**、不覆盖、不删除；无删除/改写 API。只有成功作业可写入（非成功作业409），未知作业/区域404。当前意见按目标取最大记录号；A→B→A是三次声明，重复点击和同号重试复用本轮记录。每任务最多500条，达到容量时拒绝新增但保留全部历史；读取每页最多200条，`until_id`固定导出快照边界。人工意见不改模型输出，不代表真值、精度提升或真实面积；无独立真值不报准确率或平方米。
