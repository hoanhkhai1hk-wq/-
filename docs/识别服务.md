# 本地识别服务：启动与演示

版本0.1.0，2026-10-15。Windows PowerShell；本机实际验证，不代表新电脑无需准备环境。

服务把上传的8波段TIFF交给已审FTW适配器，在SQLite保存输入来源、场景、模型摘要、运行状态、候选区域像素表和产物校验记录。后台串行处理，不在网页或服务进程加载Torch。网页识别入口尚未集成，当前通过下面的接口演示。

## 1 准备

在项目根目录操作。本机已有环境/文件，无需重新安装或下载：

- `.venv-p0`：Python3.11.15，运行服务与软件测试。服务代码仅使用标准库；真实验收脚本还使用该环境已有Pillow重读下载结果。
- `.venv-recognition`：Python3.14.7，继承本机已有Torch及小包，运行模型。具体依赖和迁移限制见[模型适配说明](模型适配说明.md)。
- `models/ftw-v1/3_Class_CCBY_FTW_Pretrained.ckpt`：约204MB的已核对权重；不在Git中。
- `samples/ftw_smoke/inference-img.tif`：上游公开适配样例；不在Git中。其时相/波段身份未独立核实，只作运行演示。来源及许可分项见[第三方登记](../THIRD_PARTY.md)。

对象存储所在本地卷须支持硬链接；当前项目目录已实测通过。成功/失败的暂存资料都保留，不自动清理或覆盖旧对象。

## 2 启动和停止

打开一个PowerShell窗口：

```powershell
Set-Location 'D:\AI_Workspace\Tasks\兴智杯'
$env:PYTHONDONTWRITEBYTECODE = '1'
& '.\.venv-p0\Scripts\python.exe' '.\scripts\service\serve.py'
```

预期显示“识别服务已启动：http://127.0.0.1:8506/”。健康检查地址为[本机健康检查](http://127.0.0.1:8506/health)。这些地址只在服务运行时可用。健康检查的ready字段表示相关文件存在，真实成功以作业`succeeded`及产物校验为准。

停止：在启动窗口按`Ctrl+C`；服务停止接收新作业，终止自身正在执行的识别进程树，未启动的排队作业标为`interrupted`。服务异常退出后，再次启动会将未完成作业标记中断，保留输入与日志，不自动重放。需要重新识别时由使用者明确提交一个新作业。

同一数据库、对象存储或运行目录只允许一个服务实例。误开第二个窗口会拒绝启动，不改原作业；即使更换端口也不能绕过资源所有权。锁文件不删除，进程退出后内核锁自动释放。

## 3 上传一张图并查看结果

保持服务窗口运行，在第二个PowerShell窗口执行：

```powershell
Set-Location 'D:\AI_Workspace\Tasks\兴智杯'
$Api = 'http://127.0.0.1:8506'
$ImagePath = Join-Path (Get-Location) 'samples\ftw_smoke\inference-img.tif'
$RequestId = [Guid]::NewGuid().ToString()
$Payload = @{
    filename = 'inference-img.tif'
    content_base64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes($ImagePath))
    source = 'Fields of the World公开适配样例；时相身份未核实'
    source_link = 'https://github.com/fieldsoftheworld/ftw-baselines/tree/45d7df7ea0c357f2c34182e4a7e0c4625dd43533'
    license_status = '上游公开示例；分项许可和署名见THIRD_PARTY.md'
    scene_id = 'FTW-PUBLIC-ADAPTER-DEMO'
    request_id = $RequestId
}
$Body = [Text.Encoding]::UTF8.GetBytes(($Payload | ConvertTo-Json -Depth 4))
$Job = Invoke-RestMethod "$Api/jobs" -Method Post -ContentType 'application/json; charset=utf-8' -Body $Body
$Job
```

返回作业编号`job_id`。`queued`表示排队、`running`表示运行、`succeeded`表示通过产物和入库校验、`failed`表示失败，`interrupted`表示中断。CPU推理阶段本机两次实测约3.6至5.7秒，另有子进程启动和读取耗时，不承诺其他机器的速度。

```powershell
$Detail = Invoke-RestMethod "$Api/jobs/$($Job.job_id)"
$Detail | ConvertTo-Json -Depth 8
```

过几秒再执行查询。成功后查询像素表：

```powershell
$Fields = Invoke-RestMethod "$Api/jobs/$($Job.job_id)/fields"
$Fields.regions | Select-Object -First 10
```

固定公开样例本机实际得到背景105910、田块内部74580、边界38572像素，共219062像素；722个田块内部候选连通区域。**候选区域不是已核实的真实田块数，像素不代表平方米；没有独立真值，不报告准确率。**

下载预览和其他产物，使用新目录避免覆盖自己的历史下载：

```powershell
$DownloadDir = Join-Path '.\reports\service\manual-downloads' ([Guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $DownloadDir | Out-Null
foreach ($Name in @('preview.png', 'mask.tif', 'class_pixels.csv', 'field_pixels.csv', 'run.json')) {
    Invoke-WebRequest "$Api/jobs/$($Job.job_id)/artifacts/$Name" -OutFile (Join-Path $DownloadDir $Name)
}
Invoke-Item (Join-Path $DownloadDir 'preview.png')
```

预览含输入前三波段RGB拉伸、预测类别和叠加三幅图；不是标注真值。掩膜保留空间标签，类别0背景、1田块内部、2边界、255无效像素。`run.json`保存输入/权重SHA256、634张量严格加载、参数、实际环境与边界说明。下载时重新比对完成时的产物摘要，若文件被改动则返回409，不静默交付过期结果。

## 4 接口和输入约束

|请求|作用|
|---|---|
|`GET /health`|服务及本地文件存在性|
|`POST /jobs`|上述JSON上传、持久化并排队|
|`GET /jobs`|最近100项作业|
|`GET /jobs/<id>`|来源/场景/状态、模型、类计数、下载摘要|
|`GET /jobs/<id>/fields`|候选区域编号、像素数、像素边框|
|`GET /jobs/<id>/artifacts/<name>`|仅上列五个固定产物|

上传JSON必填`filename`、`content_base64`、`source`、`scene_id`；可填`source_link`、`license_status`、`request_id`。相同幂等键和相同声明返回已有作业，不会重新识别；同键不同内容或来源/场景声明返回409。不同作业即使共用同一内容对象，也各自保留来源与运行记录。许可字段是上传者声明，不代表系统自动取得授权。

只接受JSON内联内容，不接受任意本地路径、命令或网址下载。扩展名须为`tif/tiff`，实际内容由识别CLI校验：≤40MiB、单页、8波段、单边≤4096、总像素≤1048576、预估解码≤64MiB。请求JSON正文≤56MiB；元数据有长度上限。错误扩展/base64/空内容等返回4xx；伪TIFF或波段不符会形成`failed`记录并保留CLI日志。普通RGB/JPG/PNG不能送进此FTW模型；治理网页仍按原支持范围使用。

公开样例类型只由固定SHA256确认，不会因为把某个私有文件配置成样例就变成公开数据。其余默认记作用户上传，不等于真实农业观测已获验证。专门测试/合成演示部署可在启动时加`--synthetic`，把非固定公开样例的输入明确标为`synthetic_test`。

服务仅绑定`127.0.0.1`或`localhost`，校验Host/Origin，不提供公网/多用户部署能力。

## 5 数据与可选配置

默认识别表与原治理表共用`data/p0/agrolake.sqlite`，新增`rec_`表；原P0表不迁移、不覆盖。原始TIFF对象在`data/service/store/objects/`，每个作业的独立输出与日志在`data/service/runs/`。TIFF识别记录独立存储，没有冒充已通过JPG/PNG治理质检。

命令行可设置`--port`、`--db`、`--store`、`--runs`、`--worker-python`、`--cli`、`--model`、`--timeout`。相对路径以项目源码根为基准，默认超时600秒。环境变量可配置`AGROLAKE_DB`、`AGROLAKE_SERVICE_STORE`、`AGROLAKE_SERVICE_RUNS`、`AGROLAKE_SERVICE_WORKER_PYTHON`、`AGROLAKE_SERVICE_CLI`、`AGROLAKE_SERVICE_MODEL`。实际模型仍须通过可信权重摘要检查。无需API密钥，无网络模型下载。
