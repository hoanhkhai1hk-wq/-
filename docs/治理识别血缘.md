# 识别登记单治理与血缘追溯

本功能把一次成功识别的**输入登记单 JSON**收进治理目录，关联资产、版本、质量检查、识别运行、人工复核和产物摘要。登记单记录服务器已保存的事实；登记后不重新推理。

原 TIFF 仍保存在识别服务，未复制到 P0。登记单的文本质检不代表 TIFF 已通过 P0 影像质检，也不是识别前质量门禁。候选区域只按像素统计；没有独立真值，不报告准确率、真实田块数或平方米。后续整改与新版本复跑另行实现。

## 启动和操作

1. 按[网页识别说明](网页识别.md)先启动识别服务，再启动网页。两者使用同一 `AGROLAKE_DB` 和 `AGROLAKE_STORE`；默认无需另外设置。自定义路径时，在两个窗口设置相同的**绝对路径**。`AGROLAKE_STORE` 保存治理对象，`AGROLAKE_SERVICE_STORE` 保存识别输入，它们用途不同。
2. 在第8页“田块识别”运行公开适配样例，或选择已有成功任务。预期看到预测图、候选区域表、人工复核与“治理登记与血缘追溯”。产物校验失败时不显示登记入口。
3. 点击“登记输入资料”。预期显示真实的 P0 资产编号、版本编号、登记单摘要和原 TIFF 摘要。两个摘要对应不同对象。
4. 切到“数据目录与预览”，找到 `recognition-input-manifest-job-<任务号>.json`。它是 `text` 文本资产，可查看登记单和现有 P0 质量规则结果。普通刷新、查询、切任务或下载不会重复登记。
5. 回到该识别任务，可查看登记时质检、当前版本状态、来源/场景变化、输入与模型摘要、复核数和产物摘要；点击“下载治理血缘 JSON（UTF-8）”。下载是本次读取的数据库快照，含 `complete` 和各明细计数。
6. 可在“问题处置”对登记单隔离或修订来源/场景，然后返回识别页点击“刷新状态”。预期当前状态改变，登记时的事实和原识别结果保持不变。这里修改的是登记单治理元数据，不会修改 TIFF、掩膜或模型，也不等于新版本复跑。

登记结果未知时，点击“重试提交（同一请求号）”。同号同作业返回原记录；跨任务复用请求号或对已登记任务换号登记返回409，每作业始终只有一份登记。登记单与 P0 资产、版本、事件、质检在同一事务提交，失败回滚；已写出的暂存或孤立对象保留，不覆盖原文件。

对象完整性是本次查询时的字节观察；登记时质检与最近复检均有各自时间，不能当成永久有效的通过证明。完整性异常会明确告警，导出保留该诊断事实。治理明细按每类最多500行返回，包含总数、已返回数及截断标记；任何明细截断时隐藏完整 JSON 下载，原记录不删除。人工复核本身沿用每作业最多500条的既有限制。

## 接口和记录

| 接口/表 | 用途 |
|---|---|
| `POST /jobs/<id>/governance` | JSON仅接受合法 `request_id`；只登记成功任务。新建201、同号复用200、未知404、状态/冲突/损坏409 |
| `GET /jobs/<id>/lineage` | 只读；未登记也返回任务、输入、运行、复核和产物事实，`registered=false` |
| `rec_governance_links` | 每作业唯一链接，保存 `asset_id/version_id`、两种摘要、请求号及登记时快照 |
| P0既有表 | `objects/assets/asset_versions/import_events/quality_checks`保存真实文本资产；后续处置仍记入 `dispositions/meta_history` |

`registration.manifest_at_registration` 与 `quality_at_registration` 是历史快照；`registration.current` 是所链接版本的当前元数据、最新规则结论与处置记录。`job`、`run`、`reviews`、`artifacts`来自原识别表，候选区域明细仍由 `/jobs/<id>/fields`读取。登记不修改原 P0 模式版本或原识别记录。

## 验证入口

使用已有环境，无新增依赖。各次测试写独立 `reports/governance/` 子目录，不使用默认演示库。

```powershell
& '.\.venv-p0\Scripts\python.exe' '.\tests\governance\test_governance.py'
& '.\.venv-p0\Scripts\python.exe' '.\tests\governance\test_codex_regressions.py'
& '.\.venv-p0\Scripts\python.exe' '.\tests\governance\test_governance_apptest.py'
& '.\.venv-p0\Scripts\python.exe' '.\scripts\governance\real_smoke.py'
```

前三项使用明确的合成软件 fixture；最后一项使用原公开样例与真实 FTW 权重验证 HTTP、入库、摘要、复核和重启。流程测试署名不代表专家标注，软件测试通过不代表农业精度。
