# RGB结果登记与问答

RGB识别成功后，可以把结果登记到统一数据目录，再在“DeepSeek 问答”选择该任务查询事实。浏览页面、切换任务和刷新均不会自动登记、识别或请求大模型。

## 操作步骤

1. 打开“RGB 图片识别”，完成一次识别，或从“历史作业”选择已有成功记录。
2. 点击“登记到数据目录”。页面显示场景编号、两个资产版本号和实际质检结论。重复点击重新核验并返回原登记，不增加资产。
3. 在“数据目录”查找对应版本；在“场景关联”查找 `RGB-作业编号`。这是一次识别任务的技术分组，不能当作实际农田编号。
4. 打开“DeepSeek 问答”，选择“RGB 识别任务事实”，再选择对应任务。本地事实摘要立即可见，包括来源摘要、模型清单摘要、三类像素数、候选区域和登记状态。
5. 只有点击“提问”才会调用 DeepSeek。未配置或调用失败时，事实摘要仍可查看。切换任务不会混用回答；同一任务的事实或治理状态改变后，旧回答会隐藏。历史问答保留各自当时的事实快照。

## 登记的内容

| 内容 | 保存与验证方式 |
| --- | --- |
| 原始输入 | 留在RGB任务存储中，保持上传字节与SHA256；不声称原始TIFF已经通过P0质检。 |
| 派生PNG影像 | 解码为512×512 RGB后无损保存，逐像素与原图比对；作为独立影像资产质检。 |
| JSON统计记录 | 保存原始输入、模型清单和六份产物摘要、固定种子、三类像素数、全部候选区域及单位说明；作为文本资产质检。 |
| 关联记录 | P0中的 `rgb_governance_links` 连接RGB任务、场景及两个资产版本。两份导入和关联行一起提交，失败整体回滚。 |

RGB任务库仍独立保存在 `data/rgb_candidate/runs.sqlite3`。问答使用SQLite只读连接，核对原图、模型快照、六份产物和SQL明细后才提供识别统计。损坏、缺文件或库行不一致会显示缺口，不回退到其他成功任务。已登记结果还会核验P0对象、版本、资产和场景是否匹配。

## 数据边界

- 三类为田块候选、田埂、道路；面积仅为像素，没有比例尺或地理参考时不能换算平方米。
- 候选区域是掩膜的连通块，不是已核实的真实农田数量。触及图边的区域可能被裁切。
- PNG和JSON来自同一张图片，不构成独立的多源农业观测。不伪造作物、土壤、传感器或拍摄时间，缺失农业属性仍会显示为缺失。
- 来源标为RGB候选派生，许可状态为未知。文件格式质检通过不代表许可、地物分类或实测农业信息已经核实。
- 模型仍是候选版本，独立来源完整标注的新图评估尚未完成。登记不触发模型训练、推理或切换FTW/API默认模型。
- GitHub保存源码和说明；本机任务数据、原图、模型、数据库及密钥不随源码推送。其他机器需要自行配置已有模型和数据，完整新机安装仍需验收。
