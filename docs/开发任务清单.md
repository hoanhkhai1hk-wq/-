## 一 开工与资源

### T00 对照赛题取得统一模板

- **输入**：比赛两张截图、比赛要求对照表，后续可访问的官方页面和模板。
- **操作**：核对报名与提交具体时刻、团队条件、评价标准、参赛须知和材料大小限制；取得实际模板并保存版本记录。
- **产物**：`docs/比赛规则核对.md`、实际模板及来源说明。
- **完成条件**：可逐项说明哪些规则来自截图、模板或最新公告。模板未取得时继续环境与原型准备，不声称正式材料已经按模板完成。

### T01 检查工程与环境

- **输入**：摘要、AGENTS.md、SHARED_MEMORY.md、V1.3 大纲与现有文件。
- **操作**：检查 Python、Git、GPU/内存和可用空间；保留现有环境，使用独立项目环境；根据实际采用组件锁定版本。先保存本地 Git 记录，公开上传按用户范围执行。
- **产物**：`reports/环境检查.md`、依赖锁定记录、README 中的安装和启动说明。
- **完成条件**：每项结论有实际命令与结果，P0 与 AI 依赖可分离；科研原稿、聊天、凭据、数据库、缓存和权重不默认进入公开仓库。

### T02 取得可用样本与模型资料

- **输入**：`docs/OPEN_SOURCE_AUDIT.md` 中的候选和数据入口；用户后续提供的授权资料。
- **操作**：先确定一套数据与模型路线，核实条款、波段、时间窗口、预处理、权重及设备要求；取得少量真实影像和可关联属性、文本。合成样本独立登记为规则测试资料。
- **产物**：`samples/来源清单.csv`、`THIRD_PARTY.md`、模型与数据适配说明。
- **完成条件**：真实和合成资料可区分，来源与许可可查。建议准备 5 至 10 个独立真实场景；达不到时记录实际数量，不复制同图冒充独立样本。

### T03 定义数据与指标口径

- **输入**：实际样本、赛题对照表和需求记录。
- **操作**：定义资产、版本、场景、关联关系、任务、问题、指标和操作记录；建立字段、类别及单位字典。给出面向农服影像交付的需求记录与示范边界。
- **产物**：`docs/数据字典.md`、语义规则配置、指标定义与流程图。
- **完成条件**：每个指标有范围、单位、分母和版本；缺少空间信息时允许像素结果，不虚构真实面积。

## 二 治理底座

### T04 统一接入与对象目录

- **依赖**：T01、T02、T03。
- **操作**：实现影像、CSV、JSON/TXT 接入；内容哈希、来源、类型、大小和上传事件登记；给输入规格设置明确限制。
- **产物**：接入与对象存储模块、元数据表及接入测试结果。
- **完成条件**：正常文件实际入库，空文件和损坏内容可处理，同名不同内容不覆盖；精确重复可识别，每次来源声明与事件仍保留。

### T05 版本语义关联与查询

- **依赖**：T03、T04。
- **操作**：实现版本与父子关系；类别和单位映射；以 scene_id 关联影像、属性和文本；保存原值及映射依据。
- **产物**：索引、字典和关联模块，版本与查询测试。
- **完成条件**：三类内容可围绕同一场景查看；失配有原因；历史版本不重复累加进当前指标；重启应用后仍可查询。

### T06 质检处置与复检

- **依赖**：T04、T05。
- **操作**：实现空文件、解码、重复、来源、适用的影像质量和表格规则；处置、隔离、复检和规则版本关联。
- **产物**：质量规则、问题记录、至少覆盖以下情况的固定测试清单及报告。
- **完成条件**：至少包含正常对照、空文件、损坏图、精确重复、同名不同内容、模糊提示、空间信息不适用或缺失、CSV 缺列或错误单位、JSON 场景失配、元数据处置复检等情况。普通图像不因缺 CRS 一律失败；启发式阈值说明误报和适用条件。

### T07 网页分析与报告

- **依赖**：T04 至 T06。
- **操作**：制作数据目录、场景预览、质量处置、指标分析和报告页面；至少一个真实多源联合查询；导出 CSV/JSON 清单和可读报告。
- **产物**：Streamlit 界面、报告导出、关键流程截图与运行说明。
- **完成条件**：完整操作链能实际运行；界面统计与独立查询相符；导出可重新读取并定位到具体版本。模板中的外部地图、Logo 和示例内容按实际需求替换，不把远程示例当本项目结果。

## 三 AI 验证与效果

### T08 模型冒烟与正式集成

- **依赖**：冒烟阶段依赖 T01、T02；正式平台集成依赖 P0 验收。
- **操作**：先用一张适配影像在独立环境验证真实分割，再包装输入、配置、模型和输出登记。后续处理固定演示批次。对每个模型保存实际类别、空间与时间输入要求。
- **产物**：单图输入、掩膜及日志；随后产出模型适配器、运行表和可选图层。
- **完成条件**：源文件与输出文件真实存在且可重读，尺寸或坐标正确；权重条款已核查。SAM 类通用对象分割可采用人工确认田块的辅助提取路线，不能冒充五类农业自动分类。FTW 不把普通 RGB 单图替代其多波段和时间窗口输入。

这项早期冒烟用于尽早发现模型风险，随后才接入治理平台，是对旧“先单图”与 V1.1“先 P0”两种安排的建议衔接。尚未开工，实际执行顺序仍要在首次环境和数据检查后写入共享记忆。

### T09 AI 反馈治理案例

- **依赖**：T06、T08。
- **操作**：从真实模型结果登记异常候选，人工确认其原因；修订错误映射、来源、关联或处理配置；保留前后版本并同模型复跑。
- **产物**：`reports/AI反馈治理案例.md` 及对应输入、结果和记录。
- **完成条件**：至少一个真实问题链可追溯，人工判断与模型建议分开记录；没有改善时记录未解决，而不是改状态凑闭环。

### T10 固定样本对照

- **依赖**：T07 至 T09。
- **操作**：固定批次、模型、设备和任务，比较治理前后可用性、无效输出、复核耗时及多源分析耗时；有独立标注才比较精度。保存原始计时和分母。
- **产物**：`reports/效果对照.md`、原始统计表及样本清单。
- **完成条件**：方法可复做，真实业务样本与人工注入异常分别报告；没有提升或小样本限制写清楚，不把元数据补全称为分割精度提升。

### T11 WorkBuddy 辅助验收

- **依赖**：已有控制与共享记忆测试记录，以及可运行的应用。
- **操作**：复用已有协作入口，不重做已验证的 MEM 任务。新建唯一任务编号，明确允许读写范围、UI 操作、输出和验收条件，再派发一次实际页面验证。
- **产物**：`work/协作/任务/<新编号>.md`、对应独立报告、实际会话 ID 与截图。
- **完成条件**：每轮明确要求读取摘要、AGENTS.md、SHARED_MEMORY.md、WORKBUDDY.md 和任务文件；先查已有状态。Codex 复核页面结果后更新记忆。连接、认证或 UI 验证失败时记录问题，不自动重放。

## 四 材料定稿与提交准备

### T15 DeepSeek 数据问答与报告解释

- **依赖**：T05 至 T07 的事实查询与指标；涉及识别结果的问答还依赖 T08。可先围绕已验收的治理数据实现，不阻塞早期 FTW 验证。
- **用户目标**：网页、数据库和 DeepSeek API 构成可操作的系统，此项属于正式交付范围，不再是可选扩展。
- **操作**：后端通过受控的只读查询取事实摘要，将问题、场景与来源版本发送至 DeepSeek；前端显示事实、回答及引用；SQLite 保存不含密钥的问答运行。模型与参数可配置，实际接通前核对当日官方文档。
- **产物**：DeepSeek 适配器、数据问答与报告页面、配置说明、不含密钥的配置样例、来源快照与实际调用记录，以及 `reports/DeepSeek接入验收.md`。
- **成功验收**：三类问题可操作，包括当前批次待复核资料、某场景质量与识别结果解释、基于实际指标的治理报告；至少一次真实成功调用有问题、事实快照、模型、真实返回与状态。其他场景的模拟测试注明用途，不能用其替代真实功能验收。统计由程序生成，无资料时回答明确说明缺口。
- **故障验收**：未配置、认证失败、余额不足、限流、服务错误或超时均显示准确状态；本地查询仍可用；不出现伪造答案和无限重试。模型建议不能自动修改数据、质量状态或执行任意 SQL。
- **配置前提**：用户在本地配置有效 API 密钥，密钥不出现在共享记忆、前端、数据库日志、截图或 Git；默认只发送必要业务摘要。本轮不配置密钥、不发出生成请求。未具备配置或未真实连通时，T15 保持未通过，不算完整系统交付。

T15 编号后加，实际在 T12 定稿前完成，不按编号排在作品提交之后。接口参考：[官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[错误码说明](https://api-docs.deepseek.com/quick_start/error_codes/)。

### T12 对照模板组织内容与证据

- **依赖**：T00、T07 至 T10，以及 T15。
- **操作**：按实际模板编写行业背景、痛点、技术方案和案例效果；嵌入图片、代码展示、测试数据材料、部署截图与来源说明；制作真实演示视频。
- **产物**：可编辑参赛稿、证据索引与演示视频。
- **完成条件**：已实现、验证效果和后续计划分别写清楚，比赛及用户系统要求逐项有证据；DeepSeek 有真实调用记录而非静态聊天截图；素材展示在规定文档中，未经用户授权不自行发布视频或材料。

### T13 导出一个 PDF 并检查

- **依赖**：T12。
- **操作**：按报名队长信息命名，导出单个 PDF，逐页检查文字、表格、图像和二维码；在独立访问环境验证视频地址。
- **产物**：`单位简称-作品名称-队长姓名-队长手机号-日期.pdf` 及材料检查记录。
- **完成条件**：使用真实模板，必要内容齐全，图像可读，无乱码、截断或重叠；二维码可打开真实视频；符合取得的大小和页数限制。

- **操作**：建议 11 月 4 日提前提交；用户自行上传，或明确授权后再执行上传。

## 五 第一次开工的可操作顺序

先读摘要和共享记忆 → 检查环境、来源、模板和实际文件 → 取得适配样本并尽早独立真实推理 → 精简治理 P0 → 正式接入模型、反馈与对照，并接通 DeepSeek → 按模板定稿。每一步向用户说明操作、结果和下一步。MOD 是任务说明，开发按依赖顺序实施并验收；不会因为复制文字或文件存在而自动完成。
