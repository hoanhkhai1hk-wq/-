# AgroLake 本地启动与环境准备

更新于2026-10-20。当前入口为侧栏导航，网页地址为 http://127.0.0.1:8505 ，识别接口为 http://127.0.0.1:8506 。仅本机访问。

## 已有这台电脑的环境

1. 双击根目录的 `一键安装.bat`。已有环境只做依赖导入、网页依赖一致性与模型SHA256检查，不重新安装或升级。成功显示“本机环境检查通过”；缺失或安装失败返回非零退出码。
2. 双击 `一键启动.bat`。健康且属于本项目的服务会被复用，启动成功后打开8505网页；新启动服务的记录和日志位于 `reports/local-start/`，复用时在窗口输出状态。如果端口被其他程序占用，查看提示，核实占用者后处理，再重试。
3. 从侧栏进入“田块识别”“RGB 识别实验”或“DeepSeek 问答”。RGB页展示已保存实验及失败结论；启动网页不触发训练、识别或外部问答。

PowerShell中也可显式执行：

```powershell
Set-Location 'D:/AI_Workspace/Tasks/兴智杯'
& './.venv-p0/Scripts/python.exe' -B './scripts/local/setup.py' --check
& './.venv-p0/Scripts/python.exe' -B './scripts/local/startup.py' start --no-browser
& './.venv-p0/Scripts/python.exe' -B './scripts/local/startup.py' status
```

`status`只检查，不启动服务。健康检查分别为 `8505/_stcore/health` 和 `8506/health`；接口的ready字段表示必要文件存在，不能代替真实推理验收。检查脚本另外执行依赖导入和模型摘要核验，但也不加载模型或推理。

后台服务没有可关闭的可见窗口。需要停止时，先用 `status` 核实实际监听PID及本项目命令行，再停止对应进程；记录中的 `launcher_pid` 可能不同于 `listener_pid`。不要结束所有Python进程或仅凭端口号杀进程。识别服务中断与排队作业处理规则见[识别服务说明](识别服务.md)。

## 首次迁移到新电脑

完整的新电脑安装尚未验收。仓库不包含现有虚拟环境、模型、公开TIFF、业务库和训练产物；单独克隆代码不能获得本机全部演示资料。

网页环境需要Python **3.11.x**。`一键安装.bat` 在不存在 `.venv-p0` 时，使用 `py -3.11` 创建环境并安装 `requirements-p0.lock.txt`；失败立即停止，保留中断现场。不会覆盖已有但损坏的环境。没有 `py` 启动器时，使用已有3.11解释器的实际绝对路径：

```powershell
# 将示例路径替换为已有的Python3.11解释器；不需要激活或修改系统Python。
& 'C:/path/to/python311/python.exe' -B './scripts/local/setup.py' --install-web
```

识别环境仍需单独准备，不能把 `requirements-recognition.txt` 当成包含Torch的完整清单。本机 `.venv-recognition` 为Python3.14.7，通过系统包复用现有CPU Torch、torchvision和numpy，另有6个锁定小包，详见[模型适配说明](模型适配说明.md)。安装器不改此环境；缺少它或基础包时明确失败，不假报全部完成。`--base-python` 只指定新建网页环境的解释器。

模型应位于 `models/ftw-v1/3_Class_CCBY_FTW_Pretrained.ckpt`，可信SHA256为 `d04671c498c181a2bca4b9c1a82fb8dcc93384eaf55841cb6672692f6fb21d3c`；公开运行样例为 `samples/ftw_smoke/inference-img.tif`。来源、许可与署名见[第三方登记](../THIRD_PARTY.md)。样例缺失不影响服务启动，但不能执行公开样例演示。不要为解决启动问题重建现有数据库或重新导入合成样本。

## 数据与故障恢复

- 默认治理数据库：`data/p0/agrolake.sqlite`；对象：`data/p0/store/objects/`；识别运行：`data/service/runs/`。识别服务和网页默认共享同一数据库。
- `AGROLAKE_DB`、`AGROLAKE_STORE`、`AGROLAKE_DATA_DIR`、`AGROLAKE_REPORTS` 及识别配置变量可覆盖路径。环境检查和服务沿用当前进程配置，不读取或打印 `.env` 凭据。
- 启动失败先看本次日志；确认原因后再启动，不自动重新提交识别作业、覆盖历史结果或清理对象。异常退出后的作业恢复不代表重新推理成功。
- 上传8波段TIFF请选“田块识别”；普通治理影像导入不支持以Pillow代替多波段处理。候选连通区域不是确认田块数，像素不自动换算平方米。
- DeepSeek已接入并保存过真实成功记录；它仍需有效配置和网络。正式演示前需核验当时响应，不能把历史成功当当前在线。发问时选定事实摘要会发送至DeepSeek。

## 验证范围

启动与环境准备的针对性回归入口位于 `tests/local/`。旧 `scripts/p0/ui_apptest.py` 仍使用历史页签布局，不代表当前11页侧栏导航已经通过。当前导航独立验证记录见 `reports/project/Codex-INT-20261020-001/navigation-integration-v2.json`。

本地自动运行批处理而不等待按键时，可在调用前设置 `$env:AGROLAKE_NO_PAUSE='1'`；启动批处理可传 `--no-browser`，安装批处理可传 `--check`。执行完按需移除该环境变量。
